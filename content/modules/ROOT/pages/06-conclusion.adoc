== Key takeaways

1. *The platform is the product.* Individual AI capabilities are useful alone, but their value multiplies when integrated on one platform with shared observability and governance. A model endpoint is not an AI strategy.

2. *It is not just the LLM.* Every answer {assistant_name} gives depends on retrieval, tool execution, identity, and policy enforcement working together. The model is one component in a pipeline.

3. *Contrast drives understanding.* You asked the same question with no prompt, with a system prompt, with RAG, and with RAG plus the global prompt - and again with and without MCP tools. Seeing what breaks without each capability is what lets you justify investing in it.

4. *Managed services need not mean the public cloud.* MaaS gave you API keys, stable endpoints, tiers, and usage dashboards while every token stayed inside the cluster - the trade-off regulated industries actually need.

5. *Safety is not optional for production.* No single control is sufficient. Persona access controls who can ask, guardrails control what can be asked and answered, and sandboxes control what an agent can do once it is running.

6. *Observability enables trust.* When a regulator asks "why did the AI recommend this?", a trace answers with timestamps, inputs, outputs, and every decision in between.

== Next steps

* *Start with inference*: deploy a model from the catalog, then publish it through MaaS so other teams consume it instead of redeploying it
* *Ground in your data*: upload your own policy documents via the Knowledge tab and compare answers before and after
* *Trace everything*: enable MLflow tracing early, so you have a trace corpus before you need it for an incident
* *Evaluate before shipping*: wire an evaluation run into your prompt-change workflow, so a quality drop blocks the change the way a failing test blocks a merge
* *Secure your agents*: start deny-by-default and open up only what the agent proves it needs
