One API. Any framework. Any backend.

Fed Aura Capital's engineering teams have built agents using different frameworks and providers. The borrower-facing team uses LangGraph against OpenAI. The underwriting team built a risk agent using Claude. The internal SRE team experiments with open-source models on vLLM. Each team manages its own API keys, has its own governance story, and sends data to different endpoints. When the CISO asks "where does customer data go?", there is no single answer.

OGX (Open GenAI Stack) is Red Hat's implementation of the OpenAI Responses API and related agentic APIs. It provides a conformant, self-hosted alternative to calling OpenAI directly. Any framework that speaks the OpenAI standard (LangChain, LangGraph, CrewAI) can use ogx as a drop-in backend without code changes.

By the end of this module, you will be able to:

=== Key Takeaways

* ogx is the API layer, not a framework. Customers keep their framework (LangGraph, CrewAI, custom). ogx provides the governed endpoint beneath it
* Zero code migration: agents built against the OpenAI standard work unchanged. Change the base URL, keep the client code
* One governance point: instead of managing policies and credentials across multiple providers, ogx gives you a single place to enforce policies, swap backends, and log everything
* Data sovereignty: route sensitive workloads to self-hosted models. Customer data never leaves the cluster
* Provider independence: if a vendor changes pricing, deprecates a model, or has an outage, fail over without changing agent code
