.How RAG works under the hood (click to expand)
====
RAG is, at its core, about sending relevant information into the prompt so the model answers based on real data instead of hallucinating. But you cannot send the entire knowledge base - the less context you send, the faster and more accurate the reply. So the system needs a way to find the most relevant pieces automatically.

That is where **embeddings** come in. An embedding model converts text into a numerical vector - a list of numbers that captures its meaning. Similar texts produce similar vectors. This lets the system search **semantically** rather than by keyword: "minimum down payment for first-time buyers" matches "3.5% for FHA borrowers with 580+ credit score" even though they share no words.

image::module5-rag-architecture.png[RAG pipeline: documents are parsed by Docling then embedded and stored in a vector database. User queries are embedded and matched against stored vectors. Retrieved chunks are combined with the query into a context prompt sent to the LLM.,align=center]

Here is what happened when you uploaded `mortgage-products.pdf` and asked your question:

. **Chunking** - The PDF was split into smaller passages. The chunk settings you saw during upload (length 800, overlap 400) control how big each piece is and how much consecutive chunks overlap. Overlap ensures that information spanning two chunks is not lost at the boundary.
. **Embedding** - Each chunk was converted into a vector using an embedding model. The result is a numerical fingerprint of the chunk's meaning.
. **Storage** - The vectors were stored in **pgvector**, a PostgreSQL extension optimized for similarity search across millions of vectors.
. **Retrieval** - When you sent your question, it was also embedded into a vector. pgvector found the stored chunks with the most similar vectors - the ones most semantically relevant to your question.
. **Augmentation** - The retrieved chunks were injected into the model's context alongside your question, giving it access to the actual document content.
. **Generation** - The model composed its response using both its language capabilities and the retrieved facts. It cited specific rates, credit scores, and reserve requirements because those were in the retrieved chunks - not in its training data.

{company_name}'s production application uses the same pipeline. **OGX** provides the unified API layer that coordinates retrieval and generation, and **pgvector** provides the vector storage. The Playground's RAG toggle wraps this into a simple upload-and-query experience, but the same chunking, embedding, and retrieval steps run under the hood.

=== Load the platform prompt

In a production platform, you do not want every engineer writing their own system prompt from scratch. The platform admins have already deployed a **global prompt** for {assistant_name} into the cluster. Global prompts live in a dedicated `global-prompts` namespace labeled with `opendatahub.io/global-mlflow-workspace: mlflow`, which makes them available through the Prompt Registry across all projects. You do not need to configure anything - just load it.

.How global prompts work on the platform (click to expand)
====
The platform admins deployed the global prompt as a Kubernetes resource in the `global-prompts` namespace:

[source,yaml]
----
apiVersion: v1
kind: Namespace
metadata:
  name: global-prompts
  labels:
    opendatahub.io/global-mlflow-workspace: mlflow
---
apiVersion: mlflow.org/v1
kind: Prompt
metadata:
  name: fed-aura-capital-system-prompt
  namespace: global-prompts
----

The `opendatahub.io/global-mlflow-workspace: mlflow` label on the namespace tells the Prompt Registry to make all prompts in that namespace available globally. Any project in the cluster can load these prompts, but only admins can modify them. This is how the platform enforces consistent behavior across teams without requiring each engineer to copy-paste prompts manually.
====

TIP: RAG provides the facts. The system prompt provides the personality. Production AI assistants need both. The GenAI Playground lets you iterate on each independently.
