== The platform you're joining

{company_name}'s AI platform didn't arrive fully formed. It was built around four transformation pillars, each solving a specific production problem that the prototype couldn't handle. Understanding those pillars is the fastest way to understand why the platform looks the way it does today.

== The four transformation pillars

=== Pillar 1 - Fast, Flexible, and Efficient Inferencing

_"From token consumer to token producer"_

{company_name} used to pay per-token to an external LLM vendor. Every API call left the network, costs were unpredictable, and there was no control over which model version served a request.

The platform now runs self-hosted models with vLLM, a distributed inference layer with llm-d, and exposes them through a managed API gateway via Models as a Service (MaaS).

[cols="1,1",options="header"]
|===
| Before | After
| Per-token billing to external vendors | Fixed infrastructure cost, self-hosted models
| Data leaves the network on every call | Data stays in-cluster, full sovereignty
| Every team deploys its own model copy | Single deployment shared via MaaS gateway
| No usage metering or access control | Subscription tiers with API key management
|===

*Modules*: Model Catalog & Deployment, Models as a Service

=== Pillar 2 - Connecting Data to Models and Agents

_"From generic to useful AI"_

A deployed model is still generic. {assistant_name} could not quote {company_name}'s rates, did not know internal policies, and gave textbook answers with disclaimers.

The platform now shapes {assistant_name} into a domain expert through configured system prompts stored in the Prompt Registry, and grounds her responses in the bank's private documents via RAG. AutoRAG handles this at pipeline scale. OGX ties the API surface together.

[cols="1,1",options="header"]
|===
| Before | After
| Generic system prompt ("You are a helpful AI assistant") | Domain-specific persona configured for mortgage lending
| Hallucinated policy answers | RAG-grounded responses citing internal documents
| No way to update model knowledge without retraining | Upload new documents; knowledge updates in minutes
|===

*Modules*: GenAI Playground, RAG & AutoRAG, OGX

=== Pillar 3 - Accelerate Agentic AI Innovation

_"From useful to productive AI"_

{assistant_name} could answer domain-specific questions, but could not take action. When a borrower asked "How much house can I afford?", she estimated a range with assumptions. An agentic {assistant_name} calls the affordability calculator and returns a precise figure with a DTI breakdown.

The platform connects agents to real tools through the MCP Ecosystem, captures every decision path in MLflow traces, and continuously measures quality with automated evaluation pipelines.

[cols="1,1",options="header"]
|===
| Before | After
| Regular chatbot: estimates with disclaimers | Agentic chatbot: precise results from real tool calls
| Black-box agent decisions | Full MLflow traces showing every tool call and LLM invocation
| Manual quality spot-checking | Automated evaluation pipelines with EvalHub
|===

*Modules*: MCP Ecosystem, Evaluations & Tracing

=== Pillar 4 - Securing AI from Sandbox to Production

_"From prototype to production-grade"_

Agents that take real actions in a regulated industry must be secured before production. The CISO blocked deployment until a proper security model was in place. Regulators required evidence that the AI cannot be manipulated and maintains a full audit trail.

The platform now deploys NeMo Guardrails at the inference boundary, uses Garak for adversarial testing, and runs agents inside OpenShell sandboxes with deny-by-default policies and full OCSF audit logging.

[cols="1,1",options="header"]
|===
| Before | After
| No input/output filtering | NeMo Guardrails at the inference boundary
| Untested adversarial robustness | Garak adversarial test results available for review
| Agents deployed as ad-hoc containers | OpenShell with deny-by-default policies and OCSF audit logging
| No security observability | Structured audit events, SIEM-ready
|===

*Modules*: AI Safety & Secure Agent Onboarding
