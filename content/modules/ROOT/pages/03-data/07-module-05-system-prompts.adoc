=== What is a system prompt?

Before jumping into the exercises, let's clarify how prompting works. There are two parts to every prompt:

[cols="1,2,2",options="header"]
|===
| Part | What it does | Example

| **System Prompt**
| Sets the model's role and behavior. Designed by application owners. The end user never sees it.
| "You are a helpful mortgage assistant."

| **User Prompt**
| The actual question or task from the user.
| "What mortgage products do you offer?"
|===

These two parts are combined into a single input to the model. The key thing to know: the model follows the **system prompt more than the user prompt**. It has been trained to prioritize system-level instructions.

=== Why this approach breaks down

What you just did is called **context injection** - manually adding information into the prompt so the model can use it. The model did not _learn_ this data; you handed it a cheat sheet. But the cheat sheet has to fit: models have a **maximum context window**, and performance degrades as prompts get longer.

IMPORTANT: Prompt engineering is valuable for defining persona and behavior, but it is not the right tool for injecting large, changing knowledge bases. Here is why:

* **Context window limits**: Five product descriptions fit. An entire underwriting manual, compliance guide, and rate sheet library does not.
* **Maintenance burden**: When rates change or new products launch, someone must update every system prompt manually. There is no single source of truth.
* **Staleness**: The prompt is static text baked into the configuration. It does not know when information becomes outdated.
* **Scale**: {company_name} has policy documents, compliance manuals, rate sheets, product guides, and regulatory filings. You cannot paste all of them into a prompt.

When you saved the pirate prompt earlier, you used the **Prompt Registry** - a platform feature for versioning and tracking prompts. You can compare versions, roll back changes, and share prompts across teams. That solves the versioning problem. But it does not solve the knowledge problem. Even a perfectly versioned prompt cannot hold an entire document library.

The system prompt should define _who the assistant is_ and _how it behaves_. The knowledge it needs to answer questions should come from somewhere else. That somewhere else is RAG.

== Recap

[cols="1,2",options="header"]
|===
| Concept | Key takeaway

| System Prompt
| Sets model behavior. Takes priority over user input.

| User Prompt
| The question from the user. Answered within the system prompt's boundaries.

| Context injection
| Adding information into the prompt so the model can use it. Works, but does not scale.

| Context window limits
| Models have a maximum input size. You cannot paste everything.

| Prompt Registry
| Version and track prompts as platform assets. Solves versioning, not knowledge.
|===
