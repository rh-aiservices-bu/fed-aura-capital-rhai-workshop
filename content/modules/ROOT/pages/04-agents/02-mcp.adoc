{assistant_name} called five tools in her risk assessment. Those tools did not come from the LLM — they came from external servers that the platform connected her to through a standard protocol called MCP.

**MCP — Model Context Protocol** is an open standard that defines how AI agents discover and call external tools. Before MCP, connecting an agent to a tool meant hardcoding the tool's definition into the agent's code — every agent had to know about every tool it might ever use. MCP changes this: any agent that speaks the protocol can connect to any server that speaks it, without any custom integration code. Think of it like USB for AI tool access — a universal connector that works regardless of what is on either end.

The platform hosts an MCP gateway that registers tool servers centrally. Agents connect to the gateway, the gateway routes calls to the appropriate server, and the results come back through the same channel. Adding a new tool means either adding it to an existing server or registering a new one with the gateway — no changes to any agent.

== Exercise 4: The Risk MCP Server — With and Without Tools

The Risk Server MCP has a predictive AI model running behind one of its tools.

When {assistant_name} calls `uw_predict_loan_approval`, the MCP server does not apply a rules-based formula — it passes the application metrics through a scikit-learn classification model trained on historical loan application data. That model was trained using AutoML (which you can explore in the Advanced section at the end of this section). This is how {company_name} connects classical machine learning to generative AI: the LLM orchestrates and decides what to ask, and the ML model predicts.

The Risk Server exposes four tools:

[cols="1,2",options="header"]
|===
| Tool | What it does

| `calculate_dti`
| Calculates debt-to-income ratio from monthly income and total debt obligations

| `assess_asset_sufficiency`
| Verifies that the applicant's cash reserves meet the minimum threshold for the loan type

| `uw_predict_loan_approval`
| Passes application metrics through the AutoML model to produce an approval prediction

| `generate_risk_recommendation`
| Synthesizes the outputs of the other tools into a structured recommendation
|===

The difference between a chatbot and an agent is not the model — it is tool access. Let's see that difference directly by sending the same prompt with and without the Risk Server connected.

=== Without MCP

. Go to *Gen AI Studio > Playground* and create a new Playground with the `gpt-oss-120b` model. Do *not* connect any MCP tools.

. Send:
+
[source,text]
----
I have a client earning $8,000/month with $2,400 in monthly debts. What's their debt-to-income ratio and is it acceptable for a conventional mortgage?
----

. Observe the response. The model calculates DTI from the numbers you gave (30%) but hedges: "this is generally considered acceptable, but you should verify with your specific underwriting guidelines." It is doing arithmetic from the prompt — there is no tool call, no lookup against {company_name}'s actual thresholds, and no certainty.

TIP: The question was identical. The model was identical. The only difference was whether {assistant_name} had tool access. This is why MCP matters — it is not about making the model smarter, it is about giving it access to real systems with real data.

NOTE: For this exercise, the Risk MCP server requires no authentication. However, you can enforce authentication scoped per MCP server through the MCP gateway.
