From answering questions to taking action.

The data section showed RAG grounding {assistant_name} with documents. But {assistant_name} doesn't just look up facts - she calls tools, runs calculations, and coordinates across systems. When we say _tools_, we mean functions — APIs, database queries, calculators — that the agent can invoke at runtime. The model decides when and with what arguments to call a tool, but it is the agent framework that actually executes it and returns the result back to the model for further reasoning. This section covers the agentic layer: tool access via MCP, continuous evaluation with EvalHub, and utilizing a predictive AI model to power the risk assessments.

Estimated time: *25 minutes*

== Learning Objectives

By the end of this section, you will be able to:

* Observe {assistant_name} making tool calls as the Underwriter persona
* Trace a multi-step agent decision end-to-end in MLflow
* Understand MCP and explore the MCP catalog
* Use the Risk MCP server to get precise mortgage risk calculations
* Compare Playground responses with and without MCP tools
* Evaluate agent quality with EvalHub, RAGAS, and MLflow llm-as-judge

== Exercise 2: Trace the Decision in MLflow

The response looked right. But what tools ran in order to get that response? What inputs did the tools receive? What outputs did they produce? How long did each step take? MLflow captured all of it automatically!

. Navigate to *OpenShift AI Dashboard > Develop & Train > Experiments*:
+
image::agents-mlflow-experiments-nav.png[OpenShift AI Dashboard showing MLflow experiments,link=self,window=blank,width=700]

. Find the experiment called *mortgage-ai* for the mortgage-ai project and click on *Traces*. You should see a list of recent agent interactions, including the risk assessment you just triggered.
+
image::agents-mlflow-experiments-traces.png[[MLflow trace list showing recent agent interactions,link=self,window=blank,width=700]

. Locate the most recent trace for your request and click it:
+
. Switch to *Details & Timeline* tab. Walk through the trace tree from top to bottom. You will see the full decision path:
+
----
input_shield
  └── agent
        └── ChatOpenAI
              └── tool_auth
                    └── tools
                          ├── uw_application_detail
                          ├── calculate_dti
                          ├── assess_asset_sufficiency
                          ├── uw_predict_loan_approval
                          └── generate_risk_recommendation
----
+
image::agents-trace-tree.png[MLflow trace showing the full agent decision path from input_shield to tool calls,link=self,window=blank,width=700]

. Scroll down and click on the `calculate_dti` step. Inspect the inputs — the gross monthly income and total monthly debts from the application — and the output: `dti_value=29.6`. Every argument passed to the tool and every value it returned is recorded:
+
image::agents-trace-calculate-dti.png[calculate_dti tool step showing inputs and output dti_value in the trace,link=self,window=blank,width=700]

. Look at the total latency for the trace. Each step is timestamped — you can see exactly where time was spent: the LLM call, the tool auth check, each individual tool execution.

TIP: When something goes wrong in production — a wrong recommendation, a slow response, a failed tool call — this is where you go first. The trace is a full audit log of moevery decision the agent made.

=== What's Next?

You observed {assistant_name} calling tools and traced every step of her decision. But where do those tools come from? How does the platform know which tools {assistant_name} is allowed to call? And how can you give any model access to the same tools through the Playground?

That is what MCP — the Model Context Protocol — provides. In the next exercise, you will explore the MCP catalog and use the Risk Server directly. And since tool responses flow back into the model's context like any other text — invisible to the user, but fully visible to the model — you may already be wondering what happens if that content isn't trustworthy. Something we will come back to.
