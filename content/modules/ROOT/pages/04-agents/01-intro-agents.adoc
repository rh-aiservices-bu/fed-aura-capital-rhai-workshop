From answering questions to taking action.

The data module showed RAG grounding Lenora with documents. But Lenora doesn't just look up facts — she calls tools, runs calculations, and coordinates across systems. This module covers the agentic layer: tool access via MCP, continuous evaluation with EvalHub, and the predictive AI model powering risk assessments.

Estimated time: *45 minutes*

== Learning Objectives

By the end of this module, you will be able to:

* Observe Lenora making tool calls as the Loan Officer persona
* Trace a multi-step agent decision end-to-end in MLflow
* Understand MCP and explore the MCP catalog
* Use the Risk MCP server to get precise mortgage risk calculations
* Compare Playground responses with and without MCP tools
* Evaluate model quality with EvalHub, RAGAS, and MLflow llm-as-judge

== Exercise 1: Experience Fed Aura as a Loan Officer

You have already seen Lenora as a Borrower and a CEO. Now step into the Loan Officer persona — the role closest to where the AI's precision matters most. Loan officers assess risk, review applications, and make recommendations. When they ask Lenora a question, they need exact numbers, not estimates.

. Navigate to the *Fed Aura Capital App* tab. Click *Sign In* and select the *Loan Officer* persona:
+

. In the chat panel, ask:
+
[source,text]
----
Run a risk assessment on application #3730
----

. Observe the response. Lenora returns a structured risk assessment with precise numbers — DTI ratio, LTV, credit score, approval recommendation, and any conditions that apply:
+
// TODO: screenshot of risk assessment response (agents-risk-assessment-response.png)
image::agents-risk-assessment-response.png[Lenora's risk assessment response with precise figures for application 3730,link=self,window=blank,width=700]
+
This is not a chatbot estimating from general knowledge. Lenora called real tools, retrieved the application data, ran the calculations, and passed the results through a predictive model. The numbers are grounded in the actual application record.

. Ask a follow-up to see that she retains context across turns:
+
[source,text]
----
What conditions apply?
----
+
Lenora responds with the conditions from the assessment she just ran — she did not re-call the tools. The context from the previous tool call is carried forward in the conversation.

NOTE: The exact values in the response may differ depending on the cluster state, but the structure will be consistent: tool-backed precision, conditions listed by category, and a clear recommendation.

== Exercise 2: Trace the Decision in MLflow

The response looked right. But how do you verify it? What tools ran? What inputs did they receive? How long did each step take? MLflow captured all of it automatically.

. Navigate to *OpenShift AI Dashboard > Develop & Train > Experiments*:
+

. Find the experiment tagged *GenAI* for the mortgage-ai project and click on *Traces*. You should see a list of recent agent interactions, including the risk assessment you just triggered.

. Locate the most recent trace for your request and click it:
+

                    └── tools
                          ├── uw_application_detail
                          ├── calculate_dti
                          ├── assess_asset_sufficiency
                          ├── uw_predict_loan_approval
                          └── generate_risk_recommendation
----
+

. Click on the `calculate_dti` step. Inspect the inputs — the gross monthly income and total monthly debts from the application — and the output: `dti_value=29.6`. Every argument passed to the tool and every value it returned is recorded:
+
// TODO: screenshot of calculate_dti step detail (agents-trace-calculate-dti.png)

TIP: When something goes wrong in production — a wrong recommendation, a slow response, a failed tool call — this is where you go first. The trace is a full audit log of every decision the agent made.

That is what MCP — the Model Context Protocol — provides. In the next exercise, you will explore the MCP catalog and use the Risk Server directly.
