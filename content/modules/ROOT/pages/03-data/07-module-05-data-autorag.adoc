== Data Preprocessing and Document Intelligence

The product catalog you uploaded was plain text - clean, structured, and ready for chunking. That made RAG straightforward. But look at the document again: it is a simple `.txt` file with clear headings and consistent formatting.

In a real enterprise, documents rarely look like that. Mortgage companies deal with:

* PDF rate sheets with tables and footnotes
* Scanned compliance documents that need OCR
* Underwriting manuals with charts, decision trees, and embedded images
* PowerPoint presentations from product launches
* HTML pages from regulatory databases

LLMs are fundamentally text-in, text-out systems. Before a model can reason about a chart in a PDF, that chart needs to be converted to structured text. This is where document preprocessing comes in.

=== Docling: Document intelligence for RAG

Red Hat AI includes **Docling** for document preprocessing. Docling uses vision models and layout analysis to identify text blocks, tables, figures, and headers in complex documents. It preserves document structure so that chunking for RAG retains semantic boundaries - it does not split mid-table or mid-paragraph.

== Optional: AutoRAG Pipeline

WARNING: The AutoRAG pipeline takes at least *12 minutes* to complete. This section is optional and intended for participants who want to explore the automated pipeline approach.

The Playground's RAG toggle is a manual workflow - you upload files one at a time and the system processes them on the spot. This works for experimentation, but production RAG systems need to handle hundreds of documents, update automatically when new files arrive, and manage chunking and embedding parameters at scale.

AutoRAG provides the same RAG capability as an automated pipeline. You define a data source, configure chunking and embedding parameters, and the pipeline processes documents continuously. When new documents are added, the pipeline re-indexes automatically.

=== Key Takeaways

* System prompts define behavior and persona but are not the right tool for large, changing knowledge bases
* RAG grounds model responses in retrieved documents, providing current, organization-specific answers traceable to source text
* A production AI assistant combines RAG (for facts) with a tuned system prompt (for persona and style)
* Enterprise RAG pipelines require document preprocessing to handle PDFs, images, tables, and other complex formats
* Knowledge updates happen in minutes (upload a new document) instead of days or weeks (retrain the model)
