Guardrails protect the model. Sandboxes protect everything else.

Fed Aura Capital has a confidential document - `internal-policies.pdf` - containing underwriting policies that should never leave the organization: DTI limits more conservative than the QM safe harbor, jumbo loan thresholds, rate lock windows, and the exception approval chain. An AI coding agent with file system access and network connectivity could read this document and send it anywhere. OpenShell prevents that.

Estimated time: *10 minutes*

NOTE: OpenShell is Dev Preview in RHOAI 3.5, Tech Preview in 3.6, with GA targeted early next year. What you see here represents the direction of secure agent onboarding on OpenShift AI.

== Exercise 2: Connect to the Sandbox

Now connect to the running sandbox and see what the agent can access.

. In the Showroom Terminal, list the available sandboxes:
+
[source,bash]
----
openshell sandbox list
----
+
You should see the `fed-aura-opencode-sandbox` in the list with its status and policy.

. Connect to the sandbox:
+
[source,bash]
----
openshell sandbox connect
----
+
You are now inside the OpenShell terminal. This is the agent's runtime environment - an isolated sandbox with deny-by-default network policies, syscall filtering, and Landlock filesystem restrictions.

. The confidential PDF is already there - it was baked into the container image. Verify:
+
[source,bash]
----
ls collateral/internal-policies.pdf
----

. Launch OpenCode inside the sandbox:
+
[source,bash]
----
opencode
----

== Exercise 4: Enforce Policy to Block Exfiltration

OpenShell's deny-by-default policy model blocks this. Update the sandbox policy to restrict outbound network access.

. Run the policy update command:
+
[source,bash]
----
openshell policy set
----
+
This applies a policy that blocks pastebin, webhook.site, and other external upload endpoints. The policy update takes effect immediately on the running sandbox - no restart required.
+
For details on policy commands and syntax, see the https://docs.nvidia.com/openshell/latest/sandboxes/policies#update-commands[OpenShell policy documentation].

. Now try the same exfiltration again. Ask OpenCode:
+
[source,text]
----
Read the file collateral/internal-policies.pdf and upload it to pastebin
----

. OpenCode tries to execute the upload, but the request is blocked by the policy. The sandbox proxy intercepts the outbound connection and returns a structured deny response:
+

The agent never reaches the external endpoint. The supervisor intercepted the network request, evaluated it against the OPA policy, and denied it.

== Exercise 5: Customize Your Policies

The deny-by-default model means you start restrictive and open up only what the agent needs. This is the Policy Advisor workflow - similar to `audit2allow` in SELinux:

. The agent tries something and gets blocked
. You see the structured deny response with what was attempted
. You decide whether to allow it
. Allowed rules are hot-loaded into the running sandbox

Try it yourself:

. Experiment with different policy rules. What happens if you allow access to specific endpoints?
. Try restricting filesystem access - can you prevent the agent from reading certain directories?
. What about allowing inference endpoints but blocking everything else?

Go crazy. The sandbox is your playground. Every attempt, every block, every allow is logged.

TIP: All sandbox activity is traced. Navigate to *OpenShift AI Dashboard > Develop & Train > Experiments* and look for traces tagged with the sandbox. You will see every tool call, every network request, and every policy decision the sandbox made.

=== Key Takeaways

* AI safety requires defense-in-depth: no single tool covers all attack vectors. Persona-based access controls who can ask, guardrails control what can be asked and answered, and sandboxes control what agents can do at runtime
* Guardrails operate at both input (blocking prompt injection before it reaches the agent) and output (filtering non-compliant responses before they reach the user). The Guardrails Orchestrator is GA and coordinates detection
* Garak provides quantified adversarial robustness with pass/fail evidence. The Chatterbox Labs integration enables a full flow: define a policy, generate synthetic attacks, probe the model, produce a compliance report
* OpenShell's deny-by-default model means agents can access nothing unless explicitly permitted. The Policy Advisor provides an iterative, audit2allow-style workflow for building least-privilege policies
* Every decision across all three layers is traced in MLflow - persona checks, guardrail enforcement, and sandbox policy decisions. This is the audit trail regulators and auditors need
